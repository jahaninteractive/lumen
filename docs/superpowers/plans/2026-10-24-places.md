# Places Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve GPS to a place name and country locally, store it on the photo, and feed it to the inspector, filters, sidecars, exports, keywords, prompts, and digests; optional cached online lookup.

**Architecture:** One new module `geonames.py` (index build + lookup + optional online fetch), two new photo columns, a resolve step in import, and small additions at each consumer. No new dependency.

**Tech Stack:** Python stdlib sqlite3 (R-tree), urllib for the opt-in lookup, vanilla JS, unittest + Node scenarios.

**Spec:** `docs/superpowers/specs/2026-10-24-places-design.md`

## Global Constraints

- Pillow only; sqlite3/urllib stdlib. Tests never read `vendor/data`; they write 3–5 line GeoNames fixtures.
- No network unless `LUMEN_GEOCODE_ONLINE=1`; tests patch `urllib.request.urlopen` and assert no call is made when off.
- Loopback server; strict JSON; no coordinates sent anywhere by default.
- Test command `env -u LUMEN_OMLX_MODEL uv run python -W error -m unittest tests.test_<module> -v`; full suite before each commit; `node --check src/lumen/static/app.js` after JS edits.
- Commit per task with a conventional message.

## Review Focus

1. A GeoNames line with a malformed latitude or fewer than 15 columns must be skipped, not abort the index build (Task 1 test).
2. A frame with coordinates but no feature within 500 km (open ocean) must get no place and no error (Task 1 + Task 2 tests).
3. Reimport of an unchanged file with coordinates but no place must resolve one; a photo whose place was already set must not be re-resolved (Task 2 test).
4. The XMP sidecar must stay valid XML when the place contains `&` or `<` (Task 2 test).
5. With the online flag off, a miss must never call `urlopen` (Task 4 test).
