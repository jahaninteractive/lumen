# Agent project guide

Read `docs/HANDOFF.md` before changing code. It is the resumable status ledger for this project.

## Product contract

Lumen is a local, non-destructive macOS Apple Silicon photography manager for Sony `.ARW`, Leica `.DNG`, Nikon `.NEF` and Canon `.CR2`/`.CR3` raws (`domain.RAW_EXTENSIONS`). Never edit, move, rename, or delete camera originals. Derived previews, sidecars, logs, catalogs, crops, JPEGs, and astro outputs must stay inside the configured Lumen library. Crop and oMLX operations are advisory until the photographer explicitly chooses an action.

The local HTTP server must remain loopback-only and mutation routes must retain host/origin and strict JSON validation. Do not expose source paths, fingerprints, API keys, or raw model output in browser responses. Advice runs on this Mac unless the photographer has switched the AI engine in Settings to Base or Online; then resized, metadata-free previews and prompts go to that engine and nothing else does. Do not add any other network service. `Lumen.app`'s setup window runs the same pinned, photographer-chosen downloads as `scripts/bootstrap.sh` (it runs that script); the web server still contacts nothing for tools or data.

## Working style

- Keep AI vendor and model-family names out of tracked files and commit messages beyond those already there; this repo is shared and describes itself by what it does, not what built it. One exception, agreed by the photographer on 2026-11-21: the list of services Lumen can connect to (the Online presets, their one definition in `preferences.SERVICE_PRESETS`, the tests that pin it, the Settings page text that shows it, the Base hint's two home server programs, and the matching table in `README.md` and `docs/GUIDE.md`). The rule exists to keep the project agnostic about what built it; naming what it can talk to is a different thing. Model names are still never preset; the guide's "Online services tried" table may name the models a test used (asked for by the photographer, 2026-11-21). Refer to this file as `AGENTS.md`.
- Keep changes small and reuse existing patterns; Pillow is the only runtime Python dependency. Bump `__version__` in `src/lumen/__init__.py` and `pyproject.toml` together (a test pins them) and add a line to `CHANGELOG.md`.
- Use red-green tests for behavior changes and run warning-strict tests.
- Preserve the accessible native-control UI, keyboard tab behavior, live announcements, and charcoal/amber/cyan workbench.
- Keep optional tools under `vendor/apps/`; that directory is intentionally ignored by Git.
- The repository is `jahaninteractive/lumen` on GitHub; `main` is the only long-lived branch and CI runs the test suite and `node --check` on every push and pull request.
- The `.superpowers/` task snapshots and reviews are local audit material and are ignored by Git.

## Commands

```sh
zsh scripts/bootstrap.sh            # --yes accepts defaults, --no-download fetches nothing
uv run python -W error -m unittest discover -s tests -v
node --check src/lumen/static/app.js
uv run lumen doctor --json
uv run lumen serve --open
zsh scripts/build_app.sh            # dist/Lumen.app and dist/Lumen-<version>.dmg; --sign "<identity>" [--notarize <profile>]
zsh scripts/smoke_app.sh dist/Lumen.app
zsh scripts/release_app.sh           # checks only; --publish makes GitHub release v<version> (ask first). Steps: docs/RELEASING.md
```

Focused tests use `uv run python -W error -m unittest tests.test_<module> -v`.

- Native helpers are compiled by `scripts/bootstrap.sh` into `<library>/cache/bin/` (`vision_analyzer`, `raw_developer`). `raw_developer` (`tools/raw_developer.swift`, `Settings.raw_developer_path`, reported by `lumen doctor` and `/api/status`) renders raws through Core Image with the photographer's develop settings and decodes every raw JPEG export without a profile, because darktable's rawspeed refuses Sony reduced-size lossless ARW. It is required for those exports (a missing helper refuses the request naming `scripts/bootstrap.sh`); `--profile` and PNG/TIFF/HEIC exports still use darktable, and only they need it: both export routes build the pipeline with `PipelineRegistry.darktable(..., required=False)`, and without darktable such a frame fails alone with `pipelines.DARKTABLE_MISSING` (the page keeps Export enabled and disables only the profile chooser); a camera JPEG (`pipelines.CAMERA_JPEG_EXTENSIONS`) exports through decoder `camera` with no renderer at all: a full export with no crop or watermark is lossless (the camera's bytes, `quality: "lossless"`, Lumen's EXIF/XMP/IPTC written by exiftool, whose Lumen tags must precede `-TagsFromFile`), a cropped or watermarked one re-encodes once at the body's quantization tables and subsampling, share and web keep their budgets, and a non-sRGB EXIF ColorSpace is refused; `sips` is no longer in the export path. Develop settings live in `photo_develop`; saving re-renders the preview but never re-ranks the burst. The preview render also returns a 256-bucket four-channel histogram (`y` Rec. 709 luma, plus `r`, `g`, `b`), clamped to 0...1 before binning so clipped pixels land in the end buckets instead of being dropped; the widget scales to the tallest bucket outside the outer 2% of the range, so a clipping spike cannot flatten the chart. Previews decode at native scale and resample afterwards: Core Image skips raw sharpening entirely at `scaleFactor <= 0.5` and scales noise reduction with it, so a small decode previewed neither (measured 0.37s against 0.35s, because the decode dominates). The helper also reports `defaults` — the decoder's own `contrast`, `sharpness`, `luminance_nr` and `color_nr` for that file, which are not mid-range (sharpness decodes at 1.0) — and the panel parks each unset handle there. Beyond the raw amounts the helper applies `clarity` (a wide unsharp mask, radius 0.8% of the frame, slider travel capped at 0.5 intensity because wider rings a blown highlight) and `lens_correction` (a boolean; the render reports `supported.lens_correction` and the panel disables the box when the file carries no profile). Post-decode filters run at native scale with the resample last, so clarity means the same thing in the preview and the export. Core Image's `detailAmount` is deliberately not exposed: measured on these raws, 0.0 and 1.0 differ by 0.0001 mean. The noise-reduction Off/Auto/Manual mode is derived from the two amounts (unset, both zero, or anything else) rather than stored, so the mode and the amounts cannot disagree. On the Develop tab the full-size button re-renders the raw at its own size (`long_edge: 0`, which skips the viewport clamp) instead of swapping in the camera's embedded JPEG, because sharpening and noise reduction act on single pixels and a render scaled to the viewport averages them away whatever scale it decoded at; `state.develop.zoomShown` records whose full-size view the viewport holds, so leaving the tab hands it back without disturbing an embedded-JPEG zoom.

The proposal is validated by `DevelopSettings`, so a control the renderer lacks or a value outside a slider's range fails in the parser rather than at the photographer's save. No develop settings are saved: the `develop_advised` provenance event stores the proposal's `settings` and `rationale` (failures go to `develop_advice_failed`), and `Library.latest_develop_advice` reads the newest back as `advice` on `GET /api/photos/<id>`, so a reopened frame shows it again with a "Park the handles here" button; the panel parks the handles and Discard restores the fields from before the first attempt. Only `settings` and `rationale` reach the browser. Crop review is read back the same way: `Library.latest_composition_review` puts the newest `composition_reviewed` answer whose pick is still a candidate into the crops payload as `review`. Every advice call (burst critique, crop review, develop suggestion, caption, tags) runs the model with the mutation lock released and takes it only to write the result, so culling never waits on a model; the browser shows one per-panel status line (`<Label> running…`, `ready`, `failed: <reason>`) instead of a global busy flag.
- Straighten (0.10.0, on `main` since 2026-11-24; released as `v0.10.0` the same day): `domain.DEVELOP_RANGES["straighten_deg"]` is -15...15, positive turns the image clockwise as seen, exactly 0 is normalised to absent so a level frame sends no new key and a camera JPEG with no angle still exports losslessly. `composition.straightened_size`/`straightened_box` are the largest same-aspect rectangle inside the turned frame, centred and floored (on 3:2 about 5% of the pixels at 1 degree, 10% at 2, 22% at 5). `raw_developer` turns and crops at native scale straight after the decode, before clarity, curve and resample, reports `supported.straighten` and `native_width`/`native_height` (the decoded size before the turn), and scales a straightened preview from its own long edge; `rawdevelop.render_raw` refuses an angle from a helper that predates it ("The raw developer cannot straighten <name>; rebuild the helper with scripts/bootstrap.sh."), and the panel disables the group with "This Lumen's raw developer is older than straightening; run scripts/bootstrap.sh to rebuild it.".
