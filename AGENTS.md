# Agent project guide

Read `docs/HANDOFF.md` before changing code. It is the resumable status ledger for this project.

## Product contract

Lumen is a fully local, non-destructive macOS Apple Silicon photography manager for Sony `.ARW` files. Never edit, move, rename, or delete camera originals. Derived previews, sidecars, logs, catalogs, crops, JPEGs, and astro outputs must stay inside the configured Lumen library. Crop and oMLX operations are advisory until the photographer explicitly chooses an action.

The local HTTP server must remain loopback-only and mutation routes must retain host/origin and strict JSON validation. Do not expose source paths, fingerprints, API keys, or raw model output in browser responses. Do not add network services or cloud processing.

## Working style

- Keep AI vendor and model names out of tracked files and commit messages; this repo is shared and describes itself by what it does, not what built it. Refer to this file as `AGENTS.md`.
- Keep changes small and reuse existing patterns; Pillow is the only runtime Python dependency. Bump `__version__` in `src/lumen/__init__.py` and `pyproject.toml` together (a test pins them) and add a line to `CHANGELOG.md`.
- Use red-green tests for behavior changes and run warning-strict tests.
- Preserve the accessible native-control UI, keyboard tab behavior, live announcements, and charcoal/amber/cyan workbench.
- Keep optional tools under `vendor/apps/`; that directory is intentionally ignored by Git.
- The repository is `jahaninteractive/lumen` on GitHub; `main` is the only long-lived branch and CI runs the test suite and `node --check` on every push and pull request.
- The `.superpowers/` task snapshots and reviews are local audit material and are ignored by Git.

## Commands

```sh
zsh scripts/bootstrap.sh            # --yes accepts defaults, --no-download fetches nothing
uv run python -W error -m unittest discover -s tests -v
node --check src/lumen/static/app.js
uv run lumen doctor --json
uv run lumen serve --open
```

Focused tests use `uv run python -W error -m unittest tests.test_<module> -v`.

## Current tool state

- Discovery (`lumen.tools.find_tool`) checks `PATH` first, then falls back to `vendor/apps/darktable.app` / `vendor/apps/Siril.app` `Contents/MacOS/<tool>`, rejecting any resolved executable outside its bundle.
- `<library>/cache/full/` holds the camera's embedded full-size JPEGs by fingerprint (served at `GET /full/<id>`; a `.jpg` source is copied there untouched, it is its own full-size image); manual place rows (`source='manual'`) outrank every GeoNames and online row and survive index rebuilds.
- Project-local darktable: `vendor/apps/darktable.app/Contents/MacOS/darktable-cli`, version 5.6.2; `lumen doctor` reports it available. A real Sony `.ARW` export was verified 2026-10-22 (see `docs/HANDOFF.md`).
- Project-local Siril: `vendor/apps/Siril.app/Contents/MacOS/siril-cli`, Apple Silicon, version 1.4.4.
- `scripts/bootstrap.sh` is the installer. `--check` reports uv/exiftool/swiftc only (pinned by `tests/test_scripts.py`); the default asks before optional downloads; `--yes` takes defaults (implied when stdin is not a TTY); `--no-download` checks, syncs and compiles only. It fetches GeoNames into `vendor/data/geonames/` (`LUMEN_GEONAMES_COUNTRIES`), darktable 5.6.2 and Siril 1.4.4 DMGs into `vendor/downloads/` against pinned SHA-256s and copies the apps into `vendor/apps/`, oMLX 0.7.2 into `/Applications` (macOS 15+), and both models with `uvx --from huggingface_hub hf download` into oMLX's `model.model_dir`. A new tool version means a new URL and hash in the script. free-astro.org (the Siril host) intermittently resets TLS from this network; a failed optional download is listed under Skipped and a re-run resumes it.
- Native helpers are compiled by `scripts/bootstrap.sh` into `<library>/cache/bin/` (`vision_analyzer`, `raw_developer`). `raw_developer` (`tools/raw_developer.swift`, `Settings.raw_developer_path`, reported by `lumen doctor` and `/api/status`) renders raws through Core Image with the photographer's develop settings and decodes every raw JPEG export without a profile, because darktable's rawspeed refuses Sony reduced-size lossless ARW. It is required for those exports (a missing helper refuses the request naming `scripts/bootstrap.sh`); `--profile` and PNG/TIFF/HEIC exports still use darktable; a camera JPEG (`pipelines.CAMERA_JPEG_EXTENSIONS`) exports through decoder `camera` with no renderer at all: a full export with no crop or watermark is lossless (the camera's bytes, `quality: "lossless"`, Lumen's EXIF/XMP/IPTC written by exiftool, whose Lumen tags must precede `-TagsFromFile`), a cropped or watermarked one re-encodes once at the body's quantization tables and subsampling, share and web keep their budgets, and a non-sRGB EXIF ColorSpace is refused; `sips` is no longer in the export path. Develop settings live in `photo_develop`; saving re-renders the preview but never re-ranks the burst. The preview render also returns a 256-bucket four-channel histogram (`y` Rec. 709 luma, plus `r`, `g`, `b`), clamped to 0...1 before binning so clipped pixels land in the end buckets instead of being dropped; the widget scales to the tallest bucket outside the outer 2% of the range, so a clipping spike cannot flatten the chart. Previews decode at native scale and resample afterwards: Core Image skips raw sharpening entirely at `scaleFactor <= 0.5` and scales noise reduction with it, so a small decode previewed neither (measured 0.37s against 0.35s, because the decode dominates). The helper also reports `defaults` — the decoder's own `contrast`, `sharpness`, `luminance_nr` and `color_nr` for that file, which are not mid-range (sharpness decodes at 1.0) — and the panel parks each unset handle there. Beyond the raw amounts the helper applies `clarity` (a wide unsharp mask, radius 0.8% of the frame, slider travel capped at 0.5 intensity because wider rings a blown highlight) and `lens_correction` (a boolean; the render reports `lens_correction_supported` and the panel disables the box when the file carries no profile). Post-decode filters run at native scale with the resample last, so clarity means the same thing in the preview and the export. Core Image's `detailAmount` is deliberately not exposed: measured on these raws, 0.0 and 1.0 differ by 0.0001 mean. The noise-reduction Off/Auto/Manual mode is derived from the two amounts (unset, both zero, or anything else) rather than stored, so the mode and the amounts cannot disagree. On the Develop tab the full-size button re-renders the raw at its own size (`long_edge: 0`, which skips the viewport clamp) instead of swapping in the camera's embedded JPEG, because sharpening and noise reduction act on single pixels and a render scaled to the viewport averages them away whatever scale it decoded at; `state.develop.zoomShown` records whose full-size view the viewport holds, so leaving the tab hands it back without disturbing an embedded-JPEG zoom.
- `POST /api/photos/<id>/develop/suggest` (`Library.suggest_develop`, `OmlxTagger.suggest_develop`, `omlx.parse_develop_response`) is the Develop tab's "Where to start": the review-role model reads a `DEVELOP_ADVICE_LONG_EDGE` (1024) render of whatever the sliders say now plus `rawdevelop.describe_histogram` of that render's histogram, and answers with absolute values for the renderer's own controls and a rationale that names what it read. The proposal is validated by `DevelopSettings`, so a control the renderer lacks or a value outside a slider's range fails in the parser rather than at the photographer's save. No develop settings are saved: the `develop_advised` provenance event stores the proposal's `settings` and `rationale` (failures go to `develop_advice_failed`), and `Library.latest_develop_advice` reads the newest back as `advice` on `GET /api/photos/<id>`, so a reopened frame shows it again with a "Park the handles here" button; the panel parks the handles and Discard restores the fields from before the first attempt. A second attempt is the same route with the previous answer as `settings` and the photographer's words as `feedback` (capped at `web.DEVELOP_FEEDBACK_MAX`, 200), so the model critiques its own render. Only `settings` and `rationale` reach the browser. Crop review is read back the same way: `Library.latest_composition_review` puts the newest `composition_reviewed` answer whose pick is still a candidate into the crops payload as `review`. Every advice call (burst critique, crop review, develop suggestion, caption, tags) runs the model with the mutation lock released and takes it only to write the result, so culling never waits on a model; the browser shows one per-panel status line (`<Label> running…`, `ready`, `failed: <reason>`) instead of a global busy flag.
- Astro debrief (`lumen.astrodebrief`): after a run a job writes `<job>/frames.json` (each light's FITS header plus exiftool stabilisation), then deletes only `<job>/process` (never when `frames.json` is missing), and renames `result.tif`/`preview.jpg` to the EXIF stem `YYYY-MM-DD_HHMM_<camera>_<focal>mm_f<aperture>_<count>x<exposure>s_ISO<iso>`. `GET /api/astro/jobs/<id>/debrief?place=<dark_site|city|ship|handheld>` is rules only (What happened, Try now, Next time) and needs no model; `POST /api/astro/jobs/<id>/review {place}` asks the review model for notes on the preview and never changes the settings. `GET /astro/<id>/preview` serves a succeeded job's preview JPEG (`Library.astro_preview`, 404 otherwise), shown beside the debrief. The Astro tab's `#astro-place` is remembered as `lumen-astro-place`.
- Both darktable and Siril are on the user's shell `PATH` today, but the fallback finds them without it.
- darktable-cli reads the user's `~/.config/darktable` config, so Lumen pins `--core --conf plugins/lighttable/export/metadata_flags=5` (EXIF + geotag). JPEG export keeps all EXIF and GPS by user decision (2026-10-22). Every export then makes one `exiftool` pass over the finished JPEG that copies `-MakerNotes` **from the staged original** and writes IPTC IIM `Caption-Abstract` and `Keywords` (with `CodedCharacterSet=UTF8`, or IIM reads as Latin-1); `exiftool` is therefore required for every export, not only raws. The MakerNote cannot come from the render: Core Image's `writeTIFFRepresentation` carries none, and darktable's only has one because of the pin above. IPTC exists because Pillow cannot write IIM and agency ingests still read it rather than XMP.
- Every image a model sees is resized to `omlx.MODEL_IMAGE_LONG_EDGE` (1024) in `OmlxTagger._image_content`, except burst critique (`long_edge=0`), and the tag prompt asks for one-line unfenced JSON; measurements and the remaining ideas are in `docs/model-speed/HANDOFF.md`.
- oMLX status is live external state. Trust `/api/status`/`lumen doctor`, not configured model names, before claiming a model is loaded or vision-capable.
- Two model roles: `LUMEN_OMLX_FAST_MODEL` (default `Qwen3-VL-8B-Instruct-4bit`; tagging, reject scan, astro triage) and `LUMEN_OMLX_REVIEW_MODEL` (defaults to `LUMEN_OMLX_MODEL`; critique, captions, digest, composition review). Every tagger is built by `Library.tagger_for(role)`, which reads live `/api/status` and refuses an unloaded model; `lumen doctor` and `/api/status` report `omlx_roles`. `lumen serve` (`cli.serve_settings`) starts review on the full model when oMLX has it loaded, else on the fast one, unless `LUMEN_OMLX_REVIEW_MODEL` is set; the Review model and Fast model selects at the top of the batch rail (`POST /api/role-model`, `{role, model}`, role `fast` or `review`, model one of `review_models` on `/api/status`) switch either role for the running server only; hiding the rail (`#rail-toggle`) leaves a narrow strip whose Models and Batches buttons reopen it at the selects or the batch list; the fast role always starts on the fast model. The develop prompt states each control's direction because the fast model otherwise proposed -0.5 EV as a lift; the full model was measured equal or better on the same prompt. Tests patch `lumen.library.get_server_status`, `lumen.diagnostics.get_server_status`, and `lumen.library.OmlxTagger`; no test contacts oMLX.
- `LUMEN_NEAR_DUP_DISTANCE` (default 12, `0` disables) splits time bursts into near-duplicate clusters by `metrics.dhash` bit distance.
- `lumen tag --keepers` (default scope of `POST /api/photos/tag`; `tag-all` remains an alias for scope `all`). `<library>/vocabulary.json` is copied once from the packaged starter and then owned by the photographer; digests live in `<library>/digests/`.
- Remove/clear write removed frames' fingerprints to `cleared_fingerprints` (also seeded from trash snapshots); import and ingest skip them unless `--include-cleared`, and the Clear tab / `lumen cleared --remove` removes any already in the catalog. An import with `--include-cleared` is a resume: `Library._restore_cleared` -> `Catalog.restore_work` copies the frame's rating, decision, manual pick, tags, crop, develop settings, typed place name and typed position (camera fix wins) from the newest `<library>/trash/*/catalog.sqlite3` holding that fingerprint, appends `work_restored`, drops the fingerprint from the ledger, and counts it as `restored` in the import summary. Keyed by fingerprint, so a re-import from a backup drive at another path still matches. Trash is never pruned.
- Places: `Settings.geonames_dir` (env `LUMEN_GEONAMES_DIR`, default `vendor/data/geonames/`, `None` for plain `Settings(...)`) feeds `<library>/cache/geonames.sqlite`; `Library._resolve_place` stores `photos.place`/`place_country`. `Library.set_place` takes scope `frame`, `burst`, `nearby` (every catalogued frame whose fix is within `radius_km` of this one; refused without a fix on this frame) or `day` (this frame plus every frame with the same stored capture date that has neither a fix nor a place; never overwrites a typed name). `radius_km` defaults to `library.NEARBY_PLACE_KM` (5) and must be inside `NEARBY_PLACE_RANGE` (1-20); `POST /api/photos/<id>/place` requires the key on every scope, and the Edit place form sends its slider's value. `Library.set_location` (`POST /api/photos/<id>/location`, `{position, scope}`) stores a typed position (`geonames.parse_position`: decimal or degrees/minutes/seconds with hemispheres) on frames without a camera fix, scope `frame`, `burst` or `day`; `Library.location_typed` (fix equals the latest `location_set` event; `location_typed` on `/api/photos/<id>`) makes a typed fix editable, replacing that same typed position in scope; full-preset exports write it as the JPEG's GPS IFD when the render has none. Tests build GeoNames fixtures and never read `vendor/data`.
- Map: `Settings.map_dir` (env `LUMEN_MAP_DIR`, default `vendor/data/map/`, `None` for plain `Settings(...)`) holds eleven Natural Earth 1:10m GeoJSON layers (about 100 MB) that `scripts/bootstrap.sh` fetches from `nvkelso/natural-earth-vector` at a pinned commit with pinned SHA-256s: coastline, country borders, rivers, lakes, roads and populated places, plus `ne_10m_land` (kind `land`, filled), `ne_10m_geography_marine_polys` (kind `sea`, named, never filled), `ne_10m_geography_regions_polys` and `_points` (kind `mountain`, `plain`, `desert` or `region` from `featurecla`; Continent, Dragons-be-here, Lake and Null island dropped; an all-capitals name gives way to `name_en`) and `ne_10m_geography_regions_elevation_points` (kind `peak`, the name carrying `, <elevation> m`, or `<elevation> m` alone when unnamed). `MAP_FORMAT` (SQLite `user_version`) wipes an index of an older format once, so the next `ensure()` rebuilds it. The canvas's `#map-style` select (`workbench`, `natural-dark`, `natural-light`; `localStorage` key `lumen-map-style`, default `workbench`) picks the base map palette in `mapColour`; frames, clusters, the fan, tracks and the amber selection keep the workbench tokens in every style, each outlined 1.5 px in charcoal. Sea and terrain names are drawn at the centre of the clipped polygon's screen box when `rank <= zoom - 1` and the box's long side is at least 80 px; `MapIndex.query` skips `sea` and `region` rows above that rank, since they would never be drawn. `GET /api/photos/<id>` carries `photo.terrain` (names of the terrain polygons containing the fix, smallest first) read from the index and never stored; the key is absent while the index is missing, empty (just after a format wipe) or building, and a malformed polygon gives no terrain rather than a failed request. `mapdata.MapIndex` keeps `<library>/cache/map.sqlite`: a per-source-file manifest tagged `base/`, `regions/` or `overlays/` (an unchanged `ensure()` reparses nothing) and an R-tree; viewport queries (`GET /api/map/features?bbox=S,W,N,E&zoom=Z`) decimate by zoom and clip lines to the padded viewport, and answer `{"building": true}` while another request builds the index. Overlays live in `<library>/map/overlays/` (drop a `.gpx`/`.geojson` there, or `POST /api/map/overlays` `{name, text}` up to 20 MB, `DELETE /api/map/overlays/<name>`); regions in `<library>/map/regions/`, written only by `lumen map-region <name> --bbox S,W,N,E` (one Overpass request, `MAX_REGION_SQUARE_DEGREES` 4, User-Agent `Lumen/<version> (+repo URL)`, an HTTP-200 `remark` error is refused); the web server never contacts the internet for the map. `POST /api/map/overlays/<name>/geotag` (`{query, offset, max_gap_minutes, dry_run, replace}`, gap 1-120 minutes, `Library.geotag_from_track`) interpolates a position between the track points bracketing each frame's capture time, defaulting the camera clock offset to exiftool `OffsetTimeOriginal` else the Mac's zone; it writes through the typed-position path as `location_set` events with `scope: "track"` and `overlay`, never over a camera fix, and over a typed one only with `replace`; a write with `offset: null` is refused ("run the preview first so the clock offset is shown"). `GET /api/map/photos` returns `{photos, count, unfixed, cleared}`, `unfixed` counting matching frames with no fix; the group filters include `ids=3,5,8` (distinct ints, at most 200; the map's "Show all n in Review" sends it with `show_rejected=1`). `include_cleared=1` fills `cleared` with frames from every `<library>/trash/*/catalog.sqlite3` that carry a fix (newest snapshot wins per fingerprint, minus the live catalog), each with an opaque `key` (16 hex of the fingerprint's SHA-256) in place of `id` and a `thumb_url` of `/thumb/cleared/<key>` (the trashed preview through `thumbnail_for`) or `null`; the trash scan is cached in-process, keyed by the snapshots' paths and mtimes. The tab's "Everything ever imported" sends `include_cleared=1&show_rejected=1`, so live rejects show too, and draws them as hollow dots, clustered with the rest, and opens a card instead of the frame dialog. An overlay that cannot be indexed is listed with an `error` (an OS error as its `strerror`, never a path). `lumen doctor` reports `map: {dir, layers}` (`*.geojson` files directly in `map_dir`) without building the index. Tests build map fixtures and inject the Overpass opener; none reads `vendor/data/map` or reaches Overpass.
- `LUMEN_GEOCODE_ONLINE=1` (`Settings.geocode_online`, default off) lets `_resolve_place` ask Nominatim when the local result is missing or "near"; answers are cached into the index as `source='online'` rows. Tests patch `urllib.request.urlopen`; no test reaches the internet.
- The user's shell exports `LUMEN_OMLX_MODEL`, which fails `test_cli` doctor-model test; run the suite with `env -u LUMEN_OMLX_MODEL`.

`GET /api/status` carries `stale`: reasons the running server no longer matches the tree, shown first in `#system-status` and marked `data-stale`. `diagnostics.source_digest()` hashes the package's `*.py` at import and again per request, so an edit after startup is caught while a `git checkout` that only touches mtimes is not; the Swift helper is compared by mtime against its source. The reasons reach the browser, so they name no absolute paths. This exists because static files are served from disk on every request while the Python stays as imported, which makes a stale server look current and fail as whatever validation error fires first.
